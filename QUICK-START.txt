🔄 HOW IT WORKS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Automatic Saving:
└─ When you regenerate an avatar:
   1. New image is uploaded to Supabase Storage
   2. Version is saved to avatar_image_history table
   3. Edit prompt is stored with the version
   4. Traits snapshot captured
   5. Version number auto-increments
   6. Previous versions marked as not current
   7. History panel auto-refreshes

Manual Restore:
└─ When you click a previous version:
   1. Confirmation dialog appears
   2. Database function restores image_url
   3. Traits are also restored (optional)
   4. Version is marked as current
   5. Display updates to show restored image
   6. History reloads to reflect change

📊 DATABASE SCHEMA
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

avatar_image_history
├─ id: uuid (primary key)
├─ avatar_id: uuid (foreign key → avatars.id)
├─ image_url: text (full URL)
├─ version_number: integer (auto-increments)
├─ is_current: boolean (only one true per avatar)
├─ created_from: text (initial/regenerate/edit/restore)
├─ edit_prompt: text (user's prompt)
├─ traits_snapshot: jsonb (copy of traits)
└─ created_at: timestamp

Problem: History button doesn't appear
└─ Solution: Clear browser cache, hard refresh (Cmd+Shift+R)

Problem: "No history" even after regenerating
└─ Solution: Check if migration was run in Supabase

Problem: Can't restore previous version
└─ Solution: Check browser console for errors
           Check Supabase RLS policies are enabled

Problem: History shows but images don't load
└─ Solution: Check Supabase Storage bucket permissions
           Verify image URLs are still valid
